# 未核验诊断边界与财务工具路由

## 本轮解决的问题

上轮真实Flash实验虽有两题完成，模型在中间缺口中仍猜测单位、计算金额。原版Markdown会直接展开 `gaps`，补查上下文也用普通 `gaps` 字段传递。它们不应看起来像已知事实。

本轮只做离线实现与验证，没有读取密钥、发送新API请求或重跑真实模型。

## 行为变化

1. **默认报告不展开诊断原文。** 未完成状态显示程序固定的停止说明/下一步提示，而不是模型自由生成的金额、单位和解释。完整 `gaps`、候选与复核仍保留在JSON。Python诊断入口 `render_core_answer(result, include_unverified_details=True)` 可显式展示原文，标题标注“未核验，不是事实或答案”，并继续转义HTML/Markdown。没有隐藏或删除失败证据。
2. **结构化低信任标记。** 新结果包含 `diagnostics`：`trust=unverified_diagnostic`、`allowed_use=search_hint_only`、`promote_to_fact=false`，并声明可能包含错误数字、单位猜测或不可信指令。兼容保留原 `gaps` 列表；下游消费JSON必须遵循标记，不能把原字段拼接成事实记忆。
3. **补查与事实输入分开。** 补查模型接收 `unverified_diagnostic_hints` 信封，而非普通事实/缺口列表；提示明确只能用于确定待核查字段。重新回答与复核只读取原问题、证据窗口及当前候选，不接收旧缺口。财务参数解析继续只接收原始问题和授权版本；金额、单位来自原文绑定工具。
4. **历史不冒充当前事实。** `round_history` 保留原始诊断及其低信任标记。终止时重新生成当前诊断，成功后清空活动缺口，不把旧失败说明当作现行结论。`audit_boundary` 明确候选、复核、历史只是审计材料。新闭环尚无持久化/跨任务记忆，本轮不是完成了三层记忆系统。
5. **财务分支统一语义。** 新问答提示使用 `needs_financial_tools`，涵盖取数、币种/单位/口径核查和计算。旧 `needs_calculation` 仍可解析、执行并保留原状态，不修改历史记录；两者的 `next_capability` 均为financial_tools。实际子任务用 `financial_operation=extract/growth_rate/ratio` 区分，取数不会伪造计算记录。
6. **失败报告不发布残留候选。** 渲染器只在状态为answered时显示claims和候选命题判断，即使导入旧产物含有残留claims，也不会在失败报告中当答案展示。

新提示要求缺口只描述待核查字段，不在缺口里计算或猜测，但这是提示约束，不是模型永远服从的保证。信任标记也不是自然语言正确性证明；补查查询仍由模型提出，可能受错误线索影响。范围、来源、预算和财务绑定仍由代码强制检查。

## 验证

全套 **399项测试通过**，Ruff通过。新增15项覆盖：

- 默认隐藏未经核验的金额/单位/指令，JSON保留，显式诊断展示仍安全转义；
- 缺少新标记的历史结果也采用安全默认展示；失败claims/options不发布；
- 诊断列表副本和成功后的活动缺口清理；历史缺口保持低信任；
- 补查上下文使用低信任信封，旧猜测不进入后续回答、复核或财务参数解析；
- 新旧路由均可完成受支持的单体提取与同比计算，关闭财务能力后不能绕过；
- 模型不能通过自加trust字段升级诊断，不允许非回答状态携带答案claims。

这些测试使用合成文档及模拟响应，禁止网络与密钥读取，不是模型质量评测。
