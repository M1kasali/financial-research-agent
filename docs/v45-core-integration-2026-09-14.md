## 实际接入的代码

逐字节复制发布快照中的两个文件，并将来源哈希加入 `docs/source-manifest.json`：

- `vendor/agent_team_b1/focused_reasoning_v11.py`：围绕问题关键词和数值/日期选择相关连续片段。
- `vendor/agent_team_b1/option_coverage_v13.py`：为问题及候选命题分配相关证据窗口，限制文档数、窗口数及字符预算。

两文件源/目标SHA-256一致。它们属于V45发布快照的复用代码；没有声称100题全部使用同一个压缩器。原文件包含旧提示构建函数，但新入口只调用证据选择/压缩函数，不使用比赛答案槽、题号规则或锁定答案提示。

新增 `src/financial_agent/core_evidence.py`：

1. 接收现有 `TaskRequest`、授权文档版本和可选候选命题，不接收比赛qid、gold、历史答案或正确页码。
2. 通过当前受范围限制的BM25检索候选，再调用原V13/V11组件生成证据包。
3. 从固定版本语料重读候选正文，不信任调用者传入的正文/标题替换；越范围、伪造引用、源文本变化均拒绝。
4. 保留每个窗口编号对应的完整来源引用；相同原块可为不同命题产生多个窗口，不擅自去掉原算法重复选取行为。
5. 明确输出 `answer_generated=false`、`sufficiency=not_assessed` 和 `model_calls=0`。

检索当前仍是新项目的 `ScopedRetriever`，不是旧B1盲检索器的完整复刻。窗口引用绑定完整原块，不是逐字符压缩片段定位；证据相关性也不保证单位、期间或语义充分。后续回答层必须保留这些边界。

## 可运行入口

```bash
.venv/bin/financial-agent prepare \
  --chunks ../AFAC赛题四_团队方案_v1_20260712/processed_data_v1/chunks.jsonl \
  --doc annual_byd_2025_report \
  --query '核查2025年度母公司净利润，确认币种、单位和来源。'
```

可选 `--options-json '{"A":"待核查命题甲","B":"待核查命题乙"}'`；候选命题不是已知答案。默认40个候选、最多4份文档/8个窗口、6500字符。该命令不加载 `.env`，不发送网络请求，不生成答案。
