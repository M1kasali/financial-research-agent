## 实验控制

- 只从开发候选文件加载公开问题及授权文档版本，不读参考答案、审核包或旧候选回答。题目本身已用于开发，不是留出集。
- 公开问题检索一次、冻结 40 个候选；两组都使用同一 coverage 筛选、8 窗口、6500 字符上限。
- 每组执行前重新产生证据包，与预先冻结的整个包逐项比较，并回读所有来源；不一致则在模型请求前停止。两组证据包实际一致。
- 共享相同回答规则和复核规则。ID 组改变引用格式，并额外展示原文片段目录，因此并非等输入 token 实验。
- 每组最多一次回答加一次复核，最多 2 次模型请求、1 次准备工具调用、100000 估算 token 预算。固定先旧后新、每组只有一次，不推断统计显著性。
- 运行期间未修改实现；记录源码、运行脚本与辅助脚本哈希。新结果写入独立目录，关闭执行标志时不读密钥或数据、不请求模型。

## 失败与改善的具体证据

旧模式的候选有两处引用问题：

1. 平安窗口的引文删除了 PDF 正文内部换行。原文逐字匹配失败；仅在诊断中去掉来源换行才能匹配。实际准入未使用任何归一化。
2. 众安窗口的引文先写第49条，再添加 `...` 并接第48条，改变原文顺序，也不再是连续原文。即使仅去换行仍不能匹配，不能归结为简单格式差异。

旧模式在第一处校验失败时已停止，第二处问题由离线审计发现；没有请求其语义复核，没有发布其候选。

ID 模式实际选择了系统提供的两个 ID，程序回填：

- 文档 `1`，物理页11，块 `356a192b:p11:0:4e24f55da8`，字符 `[0,325)`，包含5.4条的核定期限及补充资料期间说明。
- 文档 `10`，物理页9，块 `b1d57811:p9:0:a61b318af3`，字符 `[0,356)`，包含第48—50条正文。

两处保留原换行，均通过可见窗口、原块文本、版本哈希、位置和模型原始 ID 的一致性校验。复核模块收到完整窗口和回填后的候选，对两项结论均判断支持并返回整体充分。

### 语义边界仍需注意

程序校验只能证明引用及输出链没有篡改，不能证明比较结论正确。助手阅读本次来源后，期限及补充资料通知/排除的区别能在展示的相关条款中找到对应文字；这只是开发分析，不是独立人工审核，不写入 gold。

第二项结论包含“条款中未明确……”的否定性概括。必须限定在本题指定的第48—51条范围，不能扩展为整份合同、其他产品或一般法律判断。其单个引用涵盖48—50条，第51条在同一完整窗口后段可见、供复核读取，但未包含在最终这个引用片段中。因此，否定性结论的范围与证据覆盖仍值得进一步加强；模型复核通过不消除这一局限。

## 成本与覆盖限制

回答步骤输入从 6,314 token 增至 10,619 token，增加 4,305（约68.2%），因为片段目录重复展示部分正文。ID 组另执行了6,831 token的复核，而旧模式因失败未到复核，不能将两组总费用当成等工作量的效率比较。

本次只解决该已知案例的机械引用问题，不证明其他题的成功率提高；跨文档摘要的子问题覆盖问题没有变化。维持原默认选项，保留可显式启用的 ID 模式。
