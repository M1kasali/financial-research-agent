# 分文档检索与跨页证据补查

## 已实现

保留原 `search` 行为和默认入口，新增两个可由模型选择的工具，接入 `ResearchRuntime` 工具白名单及控制器说明。

### search_documents

参数：`query`、`document_version_ids`（显式1—4个授权版本）、`top_k`（文档数至8，默认8）。

对每份文件执行范围隔离的本地检索，再按指定文档顺序轮流选取候选。同一文档版本内的完全相同文本去重；不同文档即使文字相同也保留各自出处。只做精确去重，尚未合并重叠段落。文档没有结果时不会编造命中。

上限：1次逻辑工具调用、最多4次本地索引查询、最多8个片段，每段预览1000字符。响应报告本地查询数及各文档返回数量。这不是等成本于原单次索引搜索，也不代表每份文件找到了足够证据。

### expand_context

参数：`evidence_id`（本任务已发现）、`query`（当前缺口）、`radius`（0—2，默认1）、`top_k`（1—8，默认6）。

只能从已有引用对应的同一个文档版本取证：按物理页查找同页续片/邻页候选，同时按给定 query 查找同版本内可能相距很远的说明页。两类候选交替分配，避免邻页碎片占满全部位置。无物理页信息时仍可定向搜索。响应含页距，不能误称所有返回都在邻页范围内。

上限：1次逻辑工具调用、1次本地索引查询、最多8个片段。调用者不能另传页码、文档ID来绕开种子引用。新引用进入已有证据目录，可通过 `read` 查看完整内容，并随原检查点机制保存/恢复。

补查结果都是候选证据，`accounting_context_bound=false`。没有自动将单位/主体/年份/口径写回原数值事实，没有放松 `calculate` 的拒算条件。源文件文本改动后仍拒绝读取旧引用。

## 工具验证

241项测试通过，新增23项覆盖：

- 分文档覆盖、输出上限、精确去重、不同文档出处保留。
- 空/越权/重复文档、文档数超过可分配位置、非法半径和参数拒绝。
- 同版本远页与邻页补查，未知引用、篡改引用、源文本改动拒绝。
- 新工具消费原共享逻辑调用预算；模型脚本调用、暂停、恢复后引用和调用计数保留。
- 取回上下文不自动产生事实或计算结果。

模拟模型仅验证运行链路，不证明真实模型会适时选择工具。Ruff检查通过。

### 如实保留的结果

- 分文档分支整体少命中1个参考片段，第011题退步。因此没有把它设置为默认或宣称全面优于原检索。
- 第010题原Top-8全部来自网络安全报告；分文档后同时取到寿险报告首页。但也挤出了另一个安全报告参考片段，总匹配数不变，说明均衡覆盖存在取舍。
- 第007题分文档后找到了车辆第48—51条所在页，但同时失去养老申请材料页，总参考匹配数仍不变，尚不能完成完整比较。
- 4个财务任务通过固定通用query“记账本位币 编制本财务报表 货币 单位”补查，均新增命中比亚迪2025报告物理页140。种子取自各文档首次候选，未使用预先指定的正确页码。证明该工具可取回远处说明页，不证明单位可无条件套用到每个数值。
- 第002题合并利润表、第012题公司利润表等关键数值页仍未被本轮通用单位补查解决；需要按明确缺口进一步查询表题/指标，而不是把补查到单位页当作任务完成。

## 当前边界与下一步

新代码提供了可选择的取证能力，未修改原B35方案、未验证真实模型规划，也未实现跨页数值上下文的安全绑定。当前计算器对真实语料缺少明确上下文时仍可能拒算。

下一步应做来源绑定的上下文核验：把数值行、表题、期间、单位各自绑定到具体证据，遇到母公司/合并或子公司表冲突继续拒算。随后在人工审核数据与明确的模型/预算范围内测量真实任务完成率；不能把固定探针脚本包装成自主Agent实验。

本次修改改变源码哈希，旧版本运行检查点不能静默跨版本续跑；新版本内保存恢复已有测试覆盖，不修改旧数据库。

## 复现

```bash
.venv/bin/python scripts/run_retrieval_upgrade_smoke.py --suite-directory data/local/evaluation-v2-20260913T175250Z-415e313a
.venv/bin/pytest -q
.venv/bin/ruff check src scripts tests
```

脚本是固定的工具能力探针：全体题做原始/分文档检索，只有财务领域附加通用单位查询。它不是运行时自动规划，不读取草案来选择种子或补查方向。语料预览只保存在忽略的本地实验目录，不公开上传。
