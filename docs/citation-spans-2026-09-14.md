# 可见原文片段 ID：实现与离线验证

## 本轮结果

问答入口增加可选 `--citation-mode span_id`。模型选择系统给出的片段 ID，程序回填原文和块内字符位置，再经过原有严格引用校验和单独模型语义复核。默认仍为 `verbatim`，原 V11/V13 和最高分仓库未修改。

全套 **483 项测试通过**，Ruff 通过；本轮 **0 次真实 API 请求**。这是引用协议与来源映射验证，不是模型质量、正确率、完整 Agent 验收或 B 榜成绩复现。

## 为什么做

上轮真实筛选对照中，保险比较题的 coverage 候选去掉了 PDF 原文中的换行，两处引文未能通过逐字校验，未进入语义复核，也未发布答案。详见 [原实验记录](live-selection-comparison-2026-09-14.md)。

本轮不放宽逐字匹配，也不删除原文空白。表格里的 `1 20` 与 `12 0` 不能通过空白归一化变成同一串数字。由程序从已展示正文生成 ID，可以免去模型重新抄写原文这一步，但不能解决结论错误或证据不足。

## 运行逻辑与边界

1. 从原压缩窗口中定位唯一、连续、逐字相同的原文范围；只允许识别 V11 在边缘添加的省略号，不做模糊定位或跨段拼接。位置不唯一的窗口不分配 ID。
2. 切成最多 400 字符的片段，优先句末、其次换行，保留内部空格与换行。内部硬切分避免截断连续数字；超长数字本身不给 ID。这不修复上游 PDF 提取或窗口截断，也不保证每段语义完整。
3. ID 绑定任务、会话、原问题、选项、授权版本、整个窗口集合和片段位置。新增窗口后重建目录，上一轮 ID 不可复用。最多 24 个窗口、192 个片段，超限停止。
4. 模型只能返回 `{"span_id":"提供的ID"}`，不能指定引文、窗口号或偏移。每个结论仍最多三个引用；原始响应以 `span_candidate` 单独留作审计。
5. 程序重建目录并回读来源，回填为原有 `window_number + quote` 候选，继续严格校验。复核模块看到原问题、完整窗口及回填后的候选，判断支持性、遗漏、冲突和完整性。
6. 发布前再次回读来源并验证目录与候选；通过后附带文档版本、页码、片段 ID 和块内 Unicode 码点位置 `[start, end)`。这是提取文本的位置，不是 PDF 屏幕坐标或字节偏移。

选对 ID 不等于结论成立；没有引用到不等于文档没有披露。复核拒绝、来源变化、未知 ID、跨任务 ID、预算耗尽等情况均不发布答案。补查历史保留各轮目录和原始候选。

片段目录与完整窗口同时进入回答提示，会增加输入长度，继续计入现有共享预算；本轮没有实测新增 token 或费用。此选项作用于通用证据问答，财务子流程仍使用已有字段级来源绑定，不改为模型自由选数。尚未为新问答闭环增加 SQLite 恢复。
