# 报表数值与跨页上下文绑定

## 实现结果

新增运行时工具 `bind_statement(evidence_id, context_evidence_ids, metric, expected_scope)`，不通过填补缺失字段来提升旧正则候选，而是从完整报表重新解析，并生成新的事实ID。

绑定链条分别保存主体、报表标题、年度列头、指标行、具体数值、会计期间和币种/单位的证据ID、字符范围和原文。源文件、所选单位说明和目标报表必须属于同一文档版本，同一报告主体和年份。后续计算重新解析这些来源，拒绝存储事实或上下文文本变化。计算引用包含数值页和上下文页，核验时不能省略后者。

原 `extract` 仍可返回普通文本候选供查看，但普通 `text_regex` 结果不再直接准入计算，避免把“最近的年份”当成可靠的表格列映射。原结构化 financial_row 路径保留原约束；本批没有声称所有旧结构化行也被升级为本次逐字段绑定。

## 支持范围（刻意限制）

- 完整年度报表页开头有公司年报主体/年份，且只有一个明确的合并/公司/母公司利润表或现金流量表标题。
- 显式本年及相邻上年两列，目标指标一行两值；可处理独立附注数字列。无列头、混季度、多年/多表/重复指标或未知版式拒绝。
- 指标限营业收入、净利润、归属于母公司所有者的净利润、经营活动产生的现金流量净额。
- 同版本会计政策页需具有本解析器可识别的全年期间和“编制本财务报表……人民币……单位”总体声明；支持元、千元、万元、亿元。局部单位与总体声明冲突时拒绝，不靠覆盖解决。
- 子公司/单一客户/分部等受限语境、其他发行人/年份/版本声明、主体或口径不一致、未知货币表示拒绝。
- 数字有效精度限制为最多18个数字字符，以避免缩放中间值超出当前十进制精度；未知或超出范围的输入拒绝，不静默舍入。

当前规则覆盖的是已测试的一类年度报表布局，不是通用财报/PDF理解器。即使通过规则校验，事实也标记为 `context_bound_candidate`、非人工批准。expected_scope仍需由控制器依据用户任务选择；不能把模型自己选择的口径当作用户授权。

## 真实语料组件检查

报告：`experiments/runs/statement-binding-20260914T022232Z-99305575/report.json`。

输入为分析时明确选定的来源页，隔离验证绑定/计算组件，不测试自动检索或自主规划。禁用网络socket，模型调用0。

| 检查 | 结果 |
| --- | --- |
| 合并营业收入、合并净利润、合并现金流、公司营业收入、公司净利润的两年列 | 共生成10个绑定事实 |
| 合并营业收入同比 | 3.46%，计算引用保留数值页及会计政策页 |
| 当期经营现金流/合并净利润 | 约1.75倍，使用含少数股东损益的净利润总额 |
| 公司/母公司当期营业收入 | 1,525,075人民币千元，不混用合并收入 |
| 公司/母公司当期净利润 | 4,206,012人民币千元，不混用归母净利润 |
| 合并表按母公司绑定、子公司当集团、单一客户当集团、跨报告单位、母公司/合并混算 | 5项全部拒绝 |

数字仅是对给定比赛语料的提取计算，未外部核验现实公司的财务真实性，不是投资分析结论，也不是B榜金标。

真实测试还暴露并修复了一个过严拦截：现金流量表中的“其他营业单位”不是计量单位声明，不能因包含“单位”两字而拒绝该表。已加回归测试。

## 测试与恢复

280项测试通过，新增39项，覆盖列映射、来源字符范围、局部/总体单位冲突、多份政策冲突、报表/主体/年份冲突、拒绝范围外引用、事实和原文改动、负数、精度上限、重复行、计算遗漏上下文引用的拒绝，以及模拟模型调用后的暂停/恢复。Ruff检查通过。

新工具与计算仍使用共享预算；不执行模型生成代码，不修改原比赛模块。新源码哈希使旧版本检查点不能自动跨版本续跑；不修改旧数据库，新版本内恢复已验证。

## 下一步
