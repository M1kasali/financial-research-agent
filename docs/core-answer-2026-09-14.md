# 金融长文本研究 Agent：自由任务问答入口

后续更新：CLI当前默认由 `CoreResearchEngine` 接入受限补查和财务流程，`--no-follow-up`保留本文的单次问答对照。最新默认预算、计算和补查边界见 [闭环说明](core-research-2026-09-14.md)；本文其余单次流程实现与357项测试是上一阶段记录。

## 本轮交付

在上一轮接入的V45来源V11/V13证据窗口组件之上，新增 `CoreAnswerEngine` 和 `financial-agent answer`。同一个Agent项目中，流程为：

**授权文档检索 → 原组件证据筛选/压缩 → 候选结论生成 → 程序引用校验 → 单独模型复核 → 发布答案或返回缺口。**

本入口是可供规划层调用的受约束问答能力，本身不自主规划、反复补查或执行新计算。不是V45完整复现；不使用历史题号、已保存答案、锁定答案提示或官方答案模板。

## 答案和引用

- 模型返回结构化claims，每项包含结论、类型以及窗口编号和连续原文引文。
- 程序从claims拼接最终答案，不允许额外塞入未绑定引用的总结字段。
- 引文必须同时存在于该编号窗口的实际可见正文和版本绑定的原始块中；全文其他位置出现但窗口不可见不算通过。
- 引用最终附带文档ID、版本、物理页、块ID、范围和哈希。范围仍是完整原块，不能当作精确引文坐标/PDF高亮框。
- 原组件渲染字符串保持不变；新适配器用同一原算法恢复结构化窗口，并校验重新拼接结果一致。没有按文档内“证据窗口”标题切分，因此文档伪造标题不会生成新的合法窗口编号。
- 原6500字符预算针对原证据渲染文本；结构化引用元数据和系统提示另占用量，由完整请求的TaskMeter/费用守卫检查。
- 模型复核前先校验引用，复核返回后重新校验所有保留来源及claims，源文本变化时不得发布答案。

若用户提供候选命题，每个选项必须恰好有一个支持/反驳判断，并关联有效claim；漏判、未知选项、无结论依据的判断均拒绝。不自动推断“正确的是/错误的是”的字母组合，报告展示命题判断及依据。

## 程序检查与模型判断的边界

程序可检查JSON结构、字段类型、重复键、引用编号、逐字引文、范围、版本、选项覆盖、请求预算。模型复核检查语义支持、全题覆盖、条件/例外、主体/口径/单位/期间和选项判断。

**逐字引文存在不代表结论正确；单独一次同模型复核不是独立人工gold，也不能保证免受文档诱导。** 复核失败的候选只留在JSON的 `candidate` 审计字段，不进入顶层answer/claims或Markdown正文。

派生计算要求返回 `needs_calculation`；程序拒绝显式 `calculated` claim，本入口没有自由算术工具。现有 `FinancialStatementWorkflow` 尚未自动接入此入口。模型把派生计算误标成interpretation时仍需要语义复核识别，不能宣传已经实现通用算术安全证明。

## 状态

| 状态 | 含义 |
| --- | --- |
| answered | 引用检查及模型复核通过，可展示；不是人工正确率认证 |
| abstained | 没有检索结果，或模型明确表示证据不足 |
| clarification | 模型要求补充用户需求 |
| needs_calculation | 需要调用确定性财务计算能力，尚未自动执行 |
| needs_evidence | 候选已生成，但语义复核未通过，返回缺口 |
| needs_model | 模型执行未显式启用，只准备证据 |
| validation_failed | 格式、字段、引文、范围或版本检查失败 |
| budget_exhausted | 请求前共享预算拒绝继续，不发布未复核候选 |
| needs_attention / failed | 不确定请求/接口或模型错误；不伪装成答案 |

最多一次候选生成、一次模型复核；格式或语义失败不自动修复/刷请求。底层HTTP有限重试仍逐次计入同一预算。

## 用法与安全默认值

默认只准备证据，不读 `.env`，不调用模型：

```bash
.venv/bin/financial-agent answer \
  --chunks ../AFAC赛题四_团队方案_v1_20260712/processed_data_v1/chunks.jsonl \
  --doc annual_byd_2025_report \
  --query '核查2025年度母公司净利润，确认币种、单位和来源。'
```

候选命题可通过 `--options-json` 传入。可选 `--output-dir` 必须是尚不存在的新目录，保存 `task.json`、`result.json` 和 `report.md`；非answered状态返回退出码3，命令/配置错误返回2。

只有显式加 `--execute --output-dir 新目录` 才读取当前项目 `.env` 并允许真实调用。该入口限定官方北京兼容接口、`qwen3.7-flash`、45秒请求超时、每次输出1600 token、最多4次HTTP尝试（含重试）、100,000估算token及0.25元累计费用预留。费用沿用 `BatchSpendingGuard` 的保守估算与价格快照，实际账单为准；不得把重复执行的新目录视为同一预算下的免费续跑。

真实执行目录以700模式新建，费用日志在请求前落盘；记录不含密钥或Authorization。没有加载旧比赛密钥或把整个仓库发给服务商。

当前问答执行器是**内存单次执行**，结束后输出结果，没有直接复用ResearchRuntime的SQLite恢复机制。请求结果不确定时停止；中断后不可自动重发或绕过费用日志续跑。已有ResearchRuntime持久化功能保持不变，但不能宣称新入口已经获得相同恢复能力。

## 验证

全套 **357 项测试通过**，Ruff通过。新增问答测试34项，覆盖：有效问答/引用、拒答/澄清/计算转交、伪造或不可见引文、空引用、重复claim、额外未引用答案、复核缺失/错误布尔值/未覆盖claim、源变更、选项漏判、严格JSON、共享预算、HTTP重试、超时未知用量、默认不读密钥/不访问服务、模拟执行费用日志及拒绝覆盖、报告文本转义、伪造证据标题。

离线端到端脚本：`scripts/run_core_answer_smoke.py`；产物：`experiments/runs/core-answer-simulated-20260914T032752Z-308a5ddc/`。

7个合成案例分别验证成功回答、拒答、澄清、需计算、伪造引文拒绝、复核预算耗尽和复核拒绝。执行时禁用网络，模型响应由脚本提供，`real_api_calls=0`，`answer_accuracy=null`。这些是流程检查，不能称为真实模型7题效果评测。

本轮没有执行任何真实模型请求，之前Flash试验的两题失败结果不覆盖、不改写。新问答层真实语义质量仍待验证。

另用本地BYD2025真实开发文档实际执行默认 `financial-agent answer`，产物位于 `experiments/runs/core-answer-dry-20260914/`。证据准备后正确返回 `needs_model`，模型尝试0次、费用记录为空；未加 `--execute`。默认不读取密钥还由CLI拦截测试覆盖。
