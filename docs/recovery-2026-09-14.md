# 本地持久化与断点恢复初版

## 已实现

- `storage.py`：SQLite 任务、检查点历史、模型逻辑调用与逐 attempt 账务表；事务提交保存状态。进程持有 OS 文件锁，同一数据库不允许两个运行器同时工作，进程退出后锁由 OS 释放。
- `durability.py`：绑定任务定义、整个检索库版本、源码哈希、模型配置、分词设置、Python 与关键依赖版本。密钥不进入身份指纹，允许换密钥，但不允许悄悄换模型、语料、预算或任务。
- `runtime.py`：明确区分 plan、act、execute、finished 阶段。行动决策先落盘，再执行工具；工具结果和对应内存状态共同提交。恢复从最近检查点继续，不必重新做已提交的检索/提取/计算。
- `policy.py`：成功模型响应在 JSON 解析前保存。若响应已保存、后续程序退出，则恢复时复用该响应；JSON 不合规也不会因此重新收费请求同一逻辑步骤。
- `financial-agent state --db PATH --task ID`：查看任务状态、阶段、检查点版本、逐次账务与未完成模型调用；不启动任务或发送模型请求。

数据库中的检查点包括目标、证据、事实、计算、已核验回答、事件、工具预算和重复调用记录。外部调用账务独立于步骤检查点；即使在步骤提交前退出，请求次数和保守 Token 预留也不会被恢复操作清零。

## 请求不确定性与提交边界

每次 attempt 先提交“准备发送”记录及预算，才进入传输。以下场景均不会自动重发：

- 请求途中进程退出；
- 超时/连接错误导致返回状态不确定；
- 响应可能已经收到，但尚未作为完整逻辑响应落盘就退出。

它们返回 `needs_attention`，保存已有结果和账务；反复调用恢复入口仍不会发送新请求。准备记录存在并不证明服务端实际收到了请求，只能说明本地无法安全断定其结果。当前没有接入服务端对账或人工解除该状态的接口，不应直接修改数据库绕过保护；后续需明确外部状态和重试授权。

**只承诺复用已提交结果，不宣称外部调用恰好一次。** 纯本地工具若完成计算但其结果尚未提交即退出，恢复时允许重新计算；这不产生新的外部模型请求。恢复期间的逻辑工具次数按已提交执行链计数，不是进程重启前后所有 CPU 执行次数。

计划与证据未发生变化时，已缓存模型决策使用原响应，不再根据新累计账务重新询问模型；执行器仍以恢复后的累计预算检查下一次真实请求。调用缓存会核对除瞬时预算统计之外的语义上下文，任务预算上限本身绑定在任务身份中。

## 离线验证

148 项测试通过，包括原 119 项和新增 29 项。新增覆盖：每个工具边界的暂停/恢复、完成结果缓存、预算不重置、代码/模型/任务/文档变更拒绝、凭据不落盘、并发锁、错误数据库与 schema、故障写入、超时、状态 CLI 等。

除单元测试外，执行了 4 组独立 Python 子进程实验。子进程用 `os._exit(23)` 直接退出，再启动新的 Python 进程恢复；模型传输为明确标注的假响应，子进程禁用网络。

| 退出位置 | 重启后的结果 | 重启后的新增模拟请求 | 全任务模拟请求 |
|---|---|---:|---:|
| 检索结果已提交 | 完成，复用检索结果 | 7 | 9 |
| 行动响应已保存、工具尚未执行 | 完成，复用行动响应 | 7 | 9 |
| 核验响应已保存、步骤尚未提交 | 完成，复用核验响应 | 3 | 9 |
| 请求发送阶段 | needs_attention，不重发 | 0 | 1（结果未知） |

前三种情况最终都形成同一合成财报案例的 5 次逻辑工具调用，计算结果同比增长 20.00%。无中断基线同样是 9 次模拟模型请求，恢复没有增加请求次数。**本次外部模型请求 0 次，不能据此证明真实模型效果、服务端计费或网络故障下的远端状态。**

## 使用边界与下一阶段

持久化是可选能力，不传 store 时仍是原内存运行模式。传入 `SQLiteTaskStore(Path(...))` 后，使用相同 TaskRequest、相同配置、一个新的专用模型客户端再次建立运行时并调用 `run()` 即可恢复。`run(stop_after_steps=N)` 仅用于持久化模式的安全边界暂停。已完成、预算终止、需澄清或需人工处理的状态不会自动变成新请求。

当前限定于本机可信目录、Python 3.12/WSL、editable 项目布局；POSIX 路径和进程锁已测，Windows 锁分支尚未单独验证。不支持网络文件系统、分布式 worker、热升级迁移、未知调用对账或任意任务参数变更后续跑。源码、Python 或关键依赖变化会拒绝旧状态，后续若要跨版本恢复需专门的兼容迁移设计。

数据库内有任务文本、证据与模型输出，未加密；代码不记录 API 密钥或认证请求头，但文件仍属于敏感研究数据，不要公开上传。数据库及附属文件已加入 Git 忽略。当前每个检查点保存完整快照，适合有界的小任务；长任务的增量存储、清理与备份还未实现。

下一步应建立人工核验的独立任务集和历史流程对照。在确认模型、数据外发范围和调用预算后，评价动态规划是否实际改善完整性、引用支持、拒答和成本，再推进记忆/报告/交互层；目前仍不能把比赛排名当成新 Agent 的效果指标。
